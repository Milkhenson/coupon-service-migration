# План работ с приоритетами

## 1. Роадмап по этапам

| Этап | Содержание | Выход | Статус |
|---|---|---|---|
| 1 | Юзкейсы, роли, статусная модель, edge cases | UC-1…UC-10, диаграмма ЖЦ | Готово |
| 2 | Объёмы и профиль нагрузки | RPS, часы пик, SLA p95/p99 | Готово |
| 3 | Модель данных и миграция | Целевая схема PG, маппинг, партиционирование, near-zero, сверка | В работе (детализация) |
| 4 | НФТ под нагрузку и отказоустойчивость | RPO/RTO, master+реплики, пул+балансировщик, идемпотентность, мониторинг | Готово (требования) |
| 5 | Интеграции | API кассы (синхрон/асинхрон), ETL акций, DWH, экран менеджера, генерация ключей | Готово (требования) |
| 6 | C4 L1 | Контекстная диаграмма | Готово  |

**Критерии готовности этапа:**

- Этап 1: UC-1…UC-10 описаны по шаблону; диаграмма Жизненного Цикла купона соответствует [разделу 7](01-srs-v1.0.md#7-бизнес-правила-и-статусная-модель).
- Этап 2: цифры RPS, часов пик, SLA p95/p99 зафиксированы в SRS - НФТ-1…НФТ-3.
- Этап 3: целевая схема PostgreSQL с DDL, маппинг типов, стратегия near-zero, стратегия сверки - детализированы; открытые вопросы (О-5…О-11) закрыты или приняты допущения.
- Этап 4: требования к RPO/RTO, репликации, пулу, балансировщику, идемпотентности, мониторингу зафиксированы в SRS.
- Этап 5: контракты API кассы, ETL акций, DWH, экрана менеджера, генерации ключей описаны.
- Этап 6: C4 L1 построен.

## 2. Приоритизация MoSCoW

### Must - ядро - первая очередь

- [ФТ-1](01-srs-v1.0.md#фт-1-активация-купона) активация, [ФТ-2](01-srs-v1.0.md#фт-2-проверка-купона-перед-гашением) проверка, [ФТ-3](01-srs-v1.0.md#фт-3-гашение-купона) гашение.
- [ФТ-4](01-srs-v1.0.md#фт-4-восстановление-купона) восстановление.
- Защита от двойного гашения + идемпотентность ([НФТ-6](01-srs-v1.0.md#нфт-6-идемпотентность)).
- API кассы: синхронное гашение и асинхронная активация (брокер + ключ идемпотентности).
- [ФТ-10](01-srs-v1.0.md#фт-10-логирование-событий) логирование событий в COUPON_EVENT.

### Must - инфраструктура - первая очередь

- [ФТ-5](01-srs-v1.0.md#фт-5-проверка-и-выдача-ключа-безопасности-кассы) проверка и выдача ключа + генерация ключей 25-го ночью (пакетная задача), выдача 26-го числа.
- Маппинг типов и структура целевой БД ([НФТ-10](01-srs-v1.0.md#нфт-10-совместимость-типов)), партиционирование ([ФТ-12](01-srs-v1.0.md#фт-12-партиционирование)).
- Near-zero миграция: параллельная работа двух БД, окно 5–10 мин 01:00–02:00 МСК ([НФТ-12](01-srs-v1.0.md#нфт-12-миграция)).
- Сверка после миграции (стратегия - см. [НФТ-12](01-srs-v1.0.md#нфт-12-миграция)).
- Отказоустойчивость: RPO/RTO, master + реплики, пул+балансировщик ([НФТ-4](01-srs-v1.0.md#нфт-4-доступность-и-отказоустойчивость), [НФТ-5](01-srs-v1.0.md#нфт-5-соединения)).
- [ФТ-8](01-srs-v1.0.md#фт-8-загрузка-акций) загрузка акций.
- [ФТ-6](01-srs-v1.0.md#фт-6-ручные-массовые-операции-менеджера) базовый экран менеджера: лимит 200 000, асинхронная очередь, валидация, отчёт.

### Should - вторая очередь

- [ФТ-7](01-srs-v1.0.md#фт-7-разбор-статуса-ошибка) разбор E (+ новый EVENT_TYPE, см. [06-assumptions.md](06-assumptions.md), Д-6).
- [ФТ-9](01-srs-v1.0.md#фт-9-выгрузка-в-dwh) выгрузка в DWH.
- [НФТ-9](01-srs-v1.0.md#нфт-9-наблюдаемость) мониторинг после переключения.
- Детализация стратегии сверки - ключевые атрибуты, суммы, качество данных.

### Could - третья очередь

- Расширенный формат отчёта массовых операций.
- C4 L2 (контейнеры).
- Трассировка, расширенная аналитика.

### Won't - решение принято

- Аудит действий менеджера - не нужен ([ФТ-6](01-srs-v1.0.md#фт-6-ручные-массовые-операции-менеджера)).
- Предпросмотр массовой операции - не нужен ([ФТ-6](01-srs-v1.0.md#фт-6-ручные-массовые-операции-менеджера)).
- Отдельная функция отката массовой операции - не реализуется; откат выполняется повторной массовой операцией ([ФТ-6](01-srs-v1.0.md#фт-6-ручные-массовые-операции-менеджера)).

### Вне зоны ответственности сервиса

**История изменений в DWH** - вне зоны ответственности сервиса: сервис передаёт в DWH купоны и события, а хранение истории ведёт само хранилище ([ФТ-9](01-srs-v1.0.md#фт-9-выгрузка-в-dwh)).

### Открытые вопросы и допущения

Полный реестр - в [06-assumptions.md](06-assumptions.md) (О-1…О-14, Д-1…Д-11). Влияние на работы - в разделе 3 «Порядок работ» (поле «Зависимость»).

## 3. Порядок работ - зависимости

1. **Зафиксировать статусную модель v1.0 и диаграмму ЖЦ** (E обратим через поддержку; новый EVENT_TYPE - см. [06-assumptions.md](06-assumptions.md), Д-6). Зависимость: ответы на О-1…О-4 не блокируют.
2. **Целевая схема PG и маппинг типов**; расширение COUPON_EVENT; сущность «задача массовой операции»; логика POS_KEY (ротация). Зависимость: [НФТ-10](01-srs-v1.0.md#нфт-10-совместимость-типов), [ФТ-5](01-srs-v1.0.md#фт-5-проверка-и-выдача-ключа-безопасности-кассы), [ФТ-6](01-srs-v1.0.md#фт-6-ручные-массовые-операции-менеджера).
3. **Стратегия near-zero** (dual-write vs CDC - архитектурное решение) **и сверка**. Зависимость: [НФТ-12](01-srs-v1.0.md#нфт-12-миграция); открытые вопросы О-5…О-8 (p95/p99, RTO, IOPS) - уточнить до capacity planning.
4. **API кассы**: синхронное гашение, асинхронная активация (брокер + ключ идемпотентности), проверка/выдача ключа. Зависимость: [ФТ-1](01-srs-v1.0.md#фт-1-активация-купона)…[ФТ-5](01-srs-v1.0.md#фт-5-проверка-и-выдача-ключа-безопасности-кассы), [НФТ-6](01-srs-v1.0.md#нфт-6-идемпотентность).
5. **Пакетная генерация ключей 25-го ночью** (окно 22:00–07:00 МСК). Зависимость: [ФТ-5](01-srs-v1.0.md#фт-5-проверка-и-выдача-ключа-безопасности-кассы), [НФТ-7](01-srs-v1.0.md#нфт-7-инфраструктура-и-данные).
6. **НФТ**: RPO/RTO, master+реплики, пул+балансировщик, мониторинг. Зависимость: [НФТ-4](01-srs-v1.0.md#нфт-4-доступность-и-отказоустойчивость), [НФТ-5](01-srs-v1.0.md#нфт-5-соединения), [НФТ-9](01-srs-v1.0.md#нфт-9-наблюдаемость); О-6, О-7, О-10.
7. **Интеграции**: ETL акций, DWH, экран менеджера (асинхронная очередь, отчёт). Зависимость: [ФТ-6](01-srs-v1.0.md#фт-6-ручные-массовые-операции-менеджера), [ФТ-8](01-srs-v1.0.md#фт-8-загрузка-акций), [ФТ-9](01-srs-v1.0.md#фт-9-выгрузка-в-dwh); О-1…О-4, О-11.
8. **C4 L2** - если останется время.

## 4. Риски

| Риск | Вероятность | Влияние | Меры |
|---|---|---|---|
| Генерация ключей 25-го ночью - новая пакетная задача, её нет в исходном описании | Средняя | Среднее | Оценить трудозатраты; вынести отдельной задачей; согласовать с эксплуатацией окно 22:00–07:00 |
| Асинхронная активация и массовые операции требуют брокера - архитектурное решение | Высокая | Высокое | Согласовать выбор брокера (Kafka, если эксплуатируется); заложить в план; см. [06-assumptions.md](06-assumptions.md), Д-9 |
| Near-zero миграция: механизм (двойная запись в обе БД или отдельный механизм чтения журнала Oracle — Д-8) не выбран; миграция трудоёмка | Высокая | Высокое | Вынести отдельным этапом; выбрать механизм до начала миграции; заложить сверку |
| Открытые вопросы не закрыты до начала работ: часть работ зависит от ответов (О-1…О-14) - загрузка акций (О-1…О-4), SLA (О-5), отказоустойчивость (О-6, О-7), инфраструктура (О-8), мониторинг (О-10), доставка в DWH (О-11) | Средняя | Среднее | Закрыть критичные (О-5…О-8, О-10) до capacity planning и мониторинга; остальные - по мере этапов |
